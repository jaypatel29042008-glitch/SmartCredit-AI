## 🧠 ANDREJ KARPATHY 4 CODING PRINCIPLES
Derived from Andrej Karpathy's observations on LLM coding pitfalls:

### 1. Think Before Coding
- **Don't assume. Don't hide confusion. Surface tradeoffs.**
- State assumptions explicitly. If uncertain, ask rather than guess.
- If multiple interpretations exist, present them — don't pick silently.
- Push back when warranted if a simpler approach exists.

### 2. Simplicity First
- **Minimum code that solves the problem. Nothing speculative.**
- No features beyond what was asked. No single-use abstractions.
- No "flexibility" or "configurability" that wasn't requested.
- If you write 200 lines and it could be 50, rewrite it.

### 3. Surgical Changes
- **Touch only what you must. Clean up only your own mess.**
- Don't "improve" adjacent code, comments, or formatting.
- Match existing style. Clean up your own unused imports/orphans.
- Every changed line must trace directly to the user's request.

### 4. Goal-Driven Execution
- **Define success criteria. Loop until verified.**
- Transform tasks into verifiable goals (e.g. write a test, reproduce bug, make test pass).
- For multi-step tasks, state a brief plan with verification steps.
